# The SDKs: Python, C and Rust

For a process that already holds encoded frames. All three are hosts of the
same `seyd_core::Agent`; the Python SDK is cffi over `libseyd`, the C ABI
(`sdks/c/include/seyd.h`, generated by cbindgen and checked in). The
lifecycle, rules and events are identical; only the spelling differs.

| | Python (`seyd`) | C (`seyd.h`) | Rust (`seyd_core`) |
|---|---|---|---|
| Build | `cargo build -p seyd-ffi --release`; `pip install cffi`; `PYTHONPATH=sdks/python` | `cargo build -p seyd-ffi --release`; link `-lseyd` | workspace crate |
| Create | `Agent(robot_id, signal_url, credential_path=…, qos_profile=…, max_sessions=…, quic_port=…, ipv6=…, port_mapping=…, host_override=…)` | `seyd_agent_create(&cfg, &callbacks, &agent)` | `AgentConfig { … }` |
| Channel | `add_channel(ChannelKind.VIDEO\|SENSOR\|COMMAND, name, codec=…, fps=…)` → `Channel` | `seyd_channel_add(agent, &cfg, &id)` | `ChannelSpec { id, kind, name, codec, fps, layers, max_bitrate_kbps }` in `AgentConfig.channels` |
| Layers | not exposed | `seyd_channel_add_layer(agent, ch, name, activate_above_kbps)` | `ChannelSpec.layers` |
| Start | `start()` | `seyd_agent_start(agent)` (blocks until announced, a second or two) | `Agent::start(cfg)` → `(Agent, Receiver<AgentEvent>)` |
| Video | `push_frame(ch, data, keyframe=, capture_ts_us=)` | `seyd_push_frame(agent, ch, data, len, keyframe, ts)` / `seyd_push_frame_layer(…, layer, …)` | `push_video(ch, VideoFrame { data, keyframe, capture_ts_us })` / `push_video_layer` |
| Message | `push_message(ch, bytes\|str\|Mapping)` | `seyd_push_message(agent, ch, data, len)` | `push_message(ch, &[u8])` |
| Events | `on_session_started(sid, role, path)`, `on_session_ended(sid, reason)`, `on_command(ch, payload)`, `on_requested_config(config)`, `on_recovery_request(ch, kind, reason)`, `on_signal_state(state, detail)`, `on_nat_report(report)` | the same names in `seyd_callbacks`, plus `on_layer_changed` | `AgentEvent::{SessionStarted, SessionEnded, Command, RequestedConfig, RecoveryRequest, LayerChanged, SignalConnected, SignalDisconnected, SignalDenied, NatReport}` |
| Channel by name | `channel(name)` / `channels` | `seyd_channel_id(agent, name, &id)` | `channels()` |
| Profile | `set_qos_profile(name)` | `seyd_set_qos_profile` | `set_qos_profile` |
| Status / counters | `set_status(mapping)`, `session_count`, `counters` | `seyd_set_status_json`, `seyd_session_count`, `seyd_counters` | `set_status`, `session_count`, `counters` |
| Stop | `stop()` / `close()` / `with Agent(...) as agent:` | `seyd_agent_stop`, `seyd_agent_destroy` | `stop()` |
| Logging | — | `seyd_init_logging("info")` once, before create | `tracing_subscriber::fmt().init()` |
| Errors | `SeydError` | `seyd_status` (`SEYD_OK` = 0); `seyd_last_error()` thread-local | `Result` |
| Versions | `seyd.ABI_VERSION` | `seyd_abi_version()` against `SEYD_ABI_VERSION`; `seyd_version()` is the library version string | crate version |

## The shape, in Python

```python
from seyd import Agent, ChannelKind

with Agent("my-robot", "wss://seyd-signal-flj7s44j4a-ew.a.run.app/ws",
           credential_path="/var/lib/seyd/robot.key", qos_profile="latency") as agent:
    video = agent.add_channel(ChannelKind.VIDEO, "main", codec="avc1.42001f", fps=25)
    telemetry = agent.add_channel(ChannelKind.SENSOR, "telemetry")
    agent.add_channel(ChannelKind.COMMAND, "drive")

    agent.on_command = lambda channel, payload: motors.queue(payload)      # never block here
    agent.on_session_ended = lambda sid, reason: motors.park()
    agent.on_requested_config = lambda cfg: encoder.queue_targets(cfg)     # maxBitrateKbps, maxGopMs, …
    agent.on_recovery_request = lambda ch, kind, reason: encoder.request_keyframe(kind)

    agent.start()
    for au in my_encoder:                                                   # one access unit per call
        agent.push_frame(video, au.bytes, keyframe=au.is_idr, capture_ts_us=au.pts_us)
```

The library is found via `$SEYD_LIBRARY`, then inside the package, then the
workspace's `target/release` and `target/debug`; `SeydLibraryNotFound` names
the fix. `seyd.ABI_VERSION` is the header's version. The complete robot with
its own x264 encoder is `sdks/python/examples/ffmpeg_robot.py`: x264 in a
pipe with `-bf 0`, `zerolatency`, intra refresh, `aud=insert` so access units
split without a slice parser, a keyframe flag from NAL type 5 or 7, a sensor
thread, a command handler forwarding to UDP with a non-blocking socket.

## The shape, in C

```c
seyd_init_logging("info");
seyd_callbacks cb = { .on_command = on_command, .on_session_ended = on_session_ended,
                      .on_requested_config = on_requested_config,
                      .on_recovery_request = on_recovery_request, .user = &state };
seyd_config cfg = { .robot_id = "my-robot", .signal_url = "wss://…/ws",
                    .credential_path = "/var/lib/seyd/robot.key", .qos_profile = "latency" };
seyd_agent *agent; seyd_agent_create(&cfg, &cb, &agent);          /* no network work yet */
uint8_t video, drive;
seyd_channel_config vc = { .kind = SEYD_CHANNEL_VIDEO, .name = "main", .codec = "avc1.42001f", .fps = 25 };
seyd_channel_add(agent, &vc, &video);                              /* only before start; ids from 1 */
seyd_channel_config cc = { .kind = SEYD_CHANNEL_COMMAND, .name = "drive" };
seyd_channel_add(agent, &cc, &drive);
seyd_agent_start(agent);                                           /* blocks until announced */
for (;;) seyd_push_frame(agent, video, au, au_len, is_idr, capture_ts_us);
seyd_agent_stop(agent); seyd_agent_destroy(agent);
```

Zero `quic_port`/`max_sessions` and NULL `qos_profile` take the daemon's
defaults (4433, 4, `balanced`). Strings are borrowed for the call; Seyd
copies what it keeps. Pointers passed to a callback are valid only during
the call. `seyd_agent_stop` blocks until the callback thread has finished,
so no callback runs after it returns. Compare `seyd_abi_version()` with
`SEYD_ABI_VERSION`. `SEYD_ERR_STATE` is a call in the wrong lifecycle state;
`SEYD_ERR_BACKPRESSURE` is reserved and never returned (drops are by design
and show in the counters). Link flags per platform are in `sdks/c/Makefile`
(macOS: CoreFoundation, Security, SystemConfiguration frameworks; Linux:
`-lpthread -ldl -lm`; Windows: the DLL by path, `target/release/seyd.dll`, not `-lseyd` —
MinGW `ld` would find the static `seyd.lib` first and fail on its MSVC
objects; MSVC links `seyd.dll.lib`). `make -C sdks/c
check` runs the ABI conformance test on all three (Windows: GNU make and
MinGW gcc, an MSYS2 shell).
Simulcast: `seyd_channel_add_layer` per layer before start, then
`seyd_push_frame_layer` for every layer; set `on_layer_changed` and force a
keyframe on the incoming layer.

## The shape, in Rust

`packages/seyd-core/examples/minimal_host.rs` is the whole contract:
`AgentConfig` (same defaults as `seydd.toml`: `robot_id`, `signal_url`,
`credential_path`, `quic_port`, `ipv6`, `port_mapping`, `host_override`,
`qos_profile`, `max_sessions`, `channels`, `agent_version`,
`recovery_ladder`, `relay`), `Agent::start(cfg)` returning the handle and an
event receiver, `push_message` once a second, every event printed, `stop()`
on Ctrl-C. `packages/seydd/src/main.rs` is the reference host: one input
task per layer calling `push_video_layer`, a UDP listener per sensor channel
calling `push_message`, and an event loop that is daemon policy only. The
maintenance loop runs until `stop()` or until the receiver is dropped;
`Agent` is cheap to clone.

## Enrolment for an SDK robot

The C ABI at version 1 has no enrolment call. Enrol the key file with the
daemon's command against the same path, then start the SDK robot:

```bash
printf '[agent]\nrobot_id = "%s"\nsignal_url = "%s"\ncredential_path = "%s"\n' \
  my-robot wss://seyd-signal-flj7s44j4a-ew.a.run.app/ws /var/lib/seyd/robot.key > /tmp/enrol.toml
seydd --config /tmp/enrol.toml enrol --token seyd_enr_…
```

The daemon's `enrol` reads `robot_id`, `signal_url` and `credential_path`
from the config and nothing else (this is what `./py-robot.sh` does in a
checkout). The key file format is shared by every host.

## The rules

- Handlers run on one Seyd thread, in order, and must not block; a slow
  handler delays every later event. Do no I/O in a handler; queue and
  return.
- `push_frame` / `push_message` never block and may be called from any
  thread. Backlog drops are whole frames, counted in
  `counters.frames_dropped_backlog`; keyframes are never dropped.
- One access unit per `push_frame`, with the encoder's keyframe flag and its
  capture timestamp in microseconds.
- Park actuators in `on_session_ended`; it fires whether the pilot said
  goodbye or vanished.
- Answer `on_requested_config` and `on_recovery_request`
  (`publisher-contract.md`). An encoder in a pipe that cannot take a
  keyframe request (x264 via ffmpeg) must bound a joining pilot's wait with a
  forced IDR every `maxGopMs` instead, as the Python example does.
- `on_signal_state` reports connected, disconnected or denied; the robot is
  unreachable while signalling is down. Denied carries `unknown-robot` or
  `key-mismatch` (`access.md`).
